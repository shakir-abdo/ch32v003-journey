Copy this block to the top of `main.c` before running any example from this lesson. The examples below assume these definitions are present.

```c
typedef unsigned int u32;

// ── RCC ──────────────────────────────────────────────
#define RCC_BASE    0x40021000

// ── GPIOC ──────────────────────────────────────────────
#define GPIOC_BASE    0x40011000
#define GPIOC_BSHR      (*(volatile u32*)(GPIOC_BASE + 0x10))
#define GPIOC_BCR       (*(volatile u32*)(GPIOC_BASE + 0x14))
#define GPIOC_CFGLR     (*(volatile u32*)(GPIOC_BASE + 0x00))

// Simple busy-loop delay (enough for basic examples)
static void delay(volatile u32 cycles) {
    while (cycles--) { __asm__ volatile ("nop"); }
}
```

## 0. Why is this lesson different?

Everything we've learned so far has been about **letting the hardware help us** (UART, SPI, I2C — all of them have a peripheral inside the chip that owns the timing). For **WS2812B**, no dedicated peripheral exists. We have to time every single bit by hand with **nanosecond** precision via carefully counted `nop` instructions.

This is called **bit-banging** — driving the signal entirely in software.

---

## 1. What is a WS2812B?

A smart 3-color (RGB) LED inside a 5×5mm package with a built-in controller chip. Dozens of them are chained into strips or panels and daisy-chained through a single data wire.

**The upsides:**
- ✅ One data wire for hundreds of LEDs
- ✅ Each LED is independently colorable (24-bit color)
- ✅ Cheap (~$0.05 per LED)

**The challenge:**
- ❌ Non-standard protocol — proprietary to WorldSemi
- ❌ Extremely timing-sensitive (~150ns tolerance)
- ❌ No hardware peripheral supports it

---

## 2. The protocol — the basic unit: the bit

Each bit is sent in a fixed window of **1.25 µs**, but the HIGH/LOW ratio inside it encodes the value:

| Bit | High (T1H/T0H) | Low (T0L/T1L) | Total |
|------|----------------|----------------|------------|
| `1`  | **800 ns**     | 450 ns         | 1.25 µs |
| `0`  | **400 ns**     | 850 ns         | 1.25 µs |

Then between each **frame** (full data frame):
- **Reset signal**: ≥ 50 µs LOW

The original WS2812B tolerates ±150 ns, but newer clones sometimes accept ±300 ns. Don't rely on that leniency.

---

## 3. Color order — a classic trap

Each LED takes three bytes: **G, R, B in that order** (not R,G,B!).
Each color is 8 bits, **MSB-first** (the first bit sent is bit 7).

```c
// To turn on a full-red LED:
uint8_t green = 0x00;
uint8_t red   = 0xFF;
uint8_t blue  = 0x00;
// Send them in this order: green, then red, then blue (24 bits total)
```

> 💡 If your "red" looks "green" — that's the bug. Double-check the G-R-B order.

---

## 4. Counting nops on a CH32V003 @ 48 MHz

Clock speed = 48 MHz = `48,000,000` cycles/sec → each cycle = **20.833 ns**.

| Desired timing | Required cycles |
|------------------|-------------------|
| 400 ns (T0H)     | 19.2 ≈ **19 nops** |
| 450 ns (T1L)     | 21.6 ≈ **22 nops** |
| 800 ns (T1H)     | 38.4 ≈ **38 nops** |
| 850 ns (T0L)     | 40.8 ≈ **41 nops** |

> ⚠️ This is an estimate. In theory each `nop` takes one cycle, but the pipeline and flash wait states can shift things. **Don't trust the math — measure with the logic analyzer.**

## 5. The code — `send_bit` with inline assembly

> 💡 The `GPIOC_BSHR/BCR` definitions are in the **📋 Register definitions** block above.

```c
#define WS_PIN_MASK (1u << 1)              // PC1

#define WS_HIGH()  (GPIOC_BSHR = WS_PIN_MASK)
#define WS_LOW()   (GPIOC_BCR  = WS_PIN_MASK)

// macro that emits N consecutive nop instructions via inline assembly
#define NOP1   __asm__ volatile("nop")
#define NOP4   NOP1; NOP1; NOP1; NOP1
#define NOP8   NOP4; NOP4
#define NOP16  NOP8; NOP8
#define NOP32  NOP16; NOP16

static inline void send_1(void) {
    WS_HIGH();
    NOP32; NOP4; NOP1; NOP1;   // ~38 cycles → T1H ≈ 800 ns
    WS_LOW();
    NOP16; NOP4; NOP1; NOP1;   // ~22 cycles → T1L ≈ 450 ns
}

static inline void send_0(void) {
    WS_HIGH();
    NOP16; NOP1; NOP1; NOP1;   // ~19 cycles → T0H ≈ 400 ns
    WS_LOW();
    NOP32; NOP8; NOP1;         // ~41 cycles → T0L ≈ 850 ns
}

static inline void send_byte(uint8_t b) {
    for (int i = 7; i >= 0; i--) {
        if (b & (1 << i)) send_1();
        else              send_0();
    }
}
```

## 6. Forcibly disabling interrupts

Any interrupt (SysTick, UART RX, …) costs **tens of cycles** = it breaks the timing → the LED shows random colors.

We **must** disable interrupts while sending a frame:

```c
static inline void irq_disable(void) {
    __asm__ volatile ("csrci mstatus, 8");   // clear MIE bit
}
static inline void irq_enable(void) {
    __asm__ volatile ("csrsi mstatus, 8");   // set MIE bit
}
```

> 🔑 On RISC-V, `csrci mstatus, 8` clears the MIE (Machine Interrupt Enable) bit in `mstatus`. It's the equivalent of `cli` on other architectures.

---

## 7. Sending a full frame — one RGB pixel

```c
typedef struct { uint8_t r, g, b; } pixel_t;

void send_pixel(const pixel_t *p) {
    // GRB order — that's the wire order
    send_byte(p->g);
    send_byte(p->r);
    send_byte(p->b);
}

void send_strip(const pixel_t *pixels, uint16_t count) {
    irq_disable();
    for (uint16_t i = 0; i < count; i++) {
        send_pixel(&pixels[i]);
    }
    irq_enable();
    // Reset signal after the last byte: pin stays LOW
    delay(60 * 8);     // ≥ 50 µs
}
```

## 8. Full example — rainbow on a single LED

```c
// … (the earlier code above)

int main(void) {
    // HSI = 24 MHz by default at boot — no clock init needed here
    // 48 MHz clock required! Read L05.

    // PC1 = Output Push-Pull 50 MHz
    RCC_APB2PCENR |= (1u << 4)  /* IOPCEN */;
    GPIOC_CFGLR &= ~(0xF << (4 * 1));
    GPIOC_CFGLR |=  (0x3 << (4 * 1));

    pixel_t pixel = {0, 0, 0};

    while (1) {
        // Red
        pixel = (pixel_t){.r = 64, .g = 0,  .b = 0};
        send_strip(&pixel, 1);
        delay(500 * 8000);

        // Green
        pixel = (pixel_t){.r = 0,  .g = 64, .b = 0};
        send_strip(&pixel, 1);
        delay(500 * 8000);

        // Blue
        pixel = (pixel_t){.r = 0,  .g = 0,  .b = 64};
        send_strip(&pixel, 1);
        delay(500 * 8000);
    }
}
```

> 💡 Notice the 64/255 brightness — don't crank values to 255 unless the LED is thermally isolated. On long strips heat builds up.

## 9. Verifying with a logic analyzer

Open a tool like **PulseView** or **Saleae Logic** and hook the analyzer to PC1:

| What you expect | What a deviation means |
|----------|---------------|
| 800 ns ± 100 pulse for T1H | ✅ Healthy range |
| Pulse < 600 ns for T1H | ❌ Add nops |
| Pulse > 1000 ns for T1H | ❌ Remove nops |
| Random LOW lengths | An interrupt slipped through |

## 10. Advanced improvements

### Pattern: send the whole strip in one go

```c
void update_strip_async(uint8_t *buf, uint16_t bytes) {
    irq_disable();
    while (bytes--) send_byte(*buf++);
    irq_enable();
    // No need to Delay_Us — caller knows to wait ≥ 50us before next call.
}
```

### Pattern: color wheel

```c
pixel_t color_wheel(uint8_t pos) {
    if (pos < 85)        return (pixel_t){pos*3,       255-pos*3,  0};
    else if (pos < 170)  return (pixel_t){255-(pos-85)*3, 0,       (pos-85)*3};
    else                 return (pixel_t){0,            (pos-170)*3, 255-(pos-170)*3};
}
```

### Brightness scaling

```c
pixel_t scale_brightness(pixel_t p, uint8_t bright) {
    return (pixel_t){
        .r = ((uint16_t)p.r * bright) / 255,
        .g = ((uint16_t)p.g * bright) / 255,
        .b = ((uint16_t)p.b * bright) / 255
    };
}
```

## 11. Common mistakes

| Symptom | Cause | Fix |
|---------|------|-------|
| "Wrong" color | G-R-B order ignored | Verify the order |
| LEDs flicker randomly | An interrupt shatters the timing | `irq_disable()` |
| First LED correct, rest random | nop count is off | Measure with the logic analyzer |
| Nothing lights up | MCU is at 24 MHz instead of 48 | Re-check L05 (PLL init) |
| Only the first LED reacts | Reset gap too short | Increase `delay(60 * 8)` |
| Colors "flash" intermittently | 5V rail bouncing | Add a 1000µF cap on the rail |
| Distant LEDs dim out | Voltage drop along the strip | Inject power every ~10 LEDs |

## 12. Exercises

1. **Loopback timing**: send a single bit (`send_1` then a long delay), measure the pulse width on a logic analyzer. Tune nops until it lands at exactly 800 ns.
2. **8-LED strip**: drive 8 sequential LEDs each with a different color.
3. **Rainbow scrolling**: use `color_wheel` and shift the colors across 16 LEDs over time.
4. **Brightness control via ADC**: hook a potentiometer to PC4 (ADC2). Read it, use it as a global brightness for every LED.
5. **Frame timing**: measure how many frames per second the MCU can push for 30, 60, and 144 LEDs.
